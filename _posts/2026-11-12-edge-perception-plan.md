이번 겨울방학 동안 진행할 프로젝트의 계획을 정리함. 앞으로 이 카테고리에 매주 짧은 기록과 단계별 정리 글을 남길 예정임.

## 왜 이 프로젝트인가

- 모델을 만드는 것보다 **이미 있는 모델을 실제 기기에서 빠르고 가볍게 돌리는 일**에 관심이 있음
- 예전에 GPT-2 matmul CUDA 커널을 Nsight Compute로 프로파일링하면서, 같은 연산도 하드웨어 사용 방식에 따라 속도가 크게 달라진다는 걸 경험함
- 이번에는 커널 하나가 아니라 **카메라 입력부터 결과 출력까지 파이프라인 전체**를 엣지 기기에서 다뤄 보려 함

## 질문 하나

> Jetson Orin Nano 8GB에서 전방 카메라 영상을 실시간(30fps, end-to-end p99 ≤ 33.3ms)으로 처리하면서, FP32 대비 정확도 하락을 1%p 이내로 지킬 수 있을까?

- 도로 위험요소(포트홀, 균열) 탐지는 **작업 대상(workload)** 이고, 이 프로젝트의 중심은 변환 → 양자화 → 컴파일러 분석 → 병목 제거임
- 30fps와 1%p는 출발점으로 정한 목표치. 첫 기준선을 잰 뒤 조정할 예정

## 환경

| 장비 | 용도 |
|---|---|
| Jetson Orin Nano 8GB (Super 모드) | 배포 대상. CPU와 GPU가 메모리를 공유하고 DLA는 없음 |
| RTX 4060 Ti PC | 학습, 양자화(QAT·캘리브레이션) |
| Galaxy S22+ (Snapdragon 8 Gen 1) | 이후 NPU 비교 실험 |

- 런타임(디코드 → 전처리 → 추론 → 후처리)은 **C++/CUDA**, 학습·양자화·평가는 Python으로 나눔
- 정확도는 정답 라벨이 있는 공개 데이터셋(RDD2022, 라이선스 확인 예정)의 고정 검증셋으로만 비교함. 직접 녹화한 주행 영상은 지연·전력 측정과 정성 평가에만 씀

## 측정 원칙

측정을 믿을 수 없으면 이후 모든 비교가 의미 없으므로 첫 단계를 측정 환경 만들기로 정함.

- 전원 모드와 클럭 고정 (`nvpmodel`, `jetson_clocks`)
- 워밍업 후 p50 / p90 / p99 지연, 같은 조건 5회 반복해 변동 확인
- 지연은 두 가지로 구분
  - GPU 추론만 (`trtexec`)
  - 프레임 디코드부터 결과까지 (내 C++ 런타임)
- 전력(`tegrastats`의 보드 입력 전력), 메모리, 온도 함께 기록

## 단계

| Level | 내용 | 확인할 것 |
|---|---|---|
| 0 | 측정 환경과 기준선 | 반복 측정 편차 3% 이하, FP32 기준 정확도 |
| 1 | ONNX → TensorRT 변환, C++ 런타임과 CUDA 전처리 커널 | 엔진 레이어 덤프로 어떤 레이어가 합쳐졌는지(fusion) 확인 |
| 2 | INT8 PTQ, 레이어별 민감도 분석, 혼합 정밀도 | Q/DQ를 넣은 위치와 엔진이 실제로 고른 정밀도 비교 |
| 3 | QAT, Nsight Systems로 파이프라인 전체 병목 분석 | 모델이 빨라져도 파이프라인이 안 빨라지는 지점 찾기 |
| 4~ | 검토 중 | 엣지 VLM 4비트 실행, 모델 2개 동시 실행 등 |

- INT8은 TensorRT 10에서 deprecated된 calibrator 방식 대신 **NVIDIA Model Optimizer로 Q/DQ 노드를 넣는 explicit 양자화**로 진행함
- 이후 같은 모델을 Galaxy S22+ NPU로 옮겨, NPU가 지원하지 않아 CPU로 넘어가는(fallback) 연산을 분석할 계획

- 매주 1편: 바꾼 것, 측정 결과, 막힌 점
- Level이 끝날 때마다: 질문 하나에 답하는 정리 글
- 모든 숫자는 GitHub 저장소의 결과 파일로 거슬러 올라갈 수 있게 링크함
- 주행 영상은 얼굴과 번호판을 가린 뒤에만 공개함
